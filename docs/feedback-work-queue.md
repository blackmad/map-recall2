# Image and game feedback

`public/canal-drive/js/feedback/browser.js` adds a **Feedback** button. Load it on a static review page to enable the same Firestore queue; it automatically adds **Add note** to image/canvas articles. For a stable model identity and dynamic view state, call `window.CanalFeedback.attach(container, {id, label, canvas, context: () => ({...})})` after creating the card. Manual landmarks use this hook for model fingerprints and orbit cameras.

Sign in with Google once, enter a note, optionally tap the captured image to record normalized coordinates, then save. **My feedback** displays up to 100 of the signed-in user's notes and their work status. Failed saves preserve local text drafts; a closed/reopened form captures the current view again. Evidence is saved with each successful note rather than being reconstructed from a later camera position. Game simulation freezes while the form is open, then resumes its existing state. WebGL screenshots are captured on demand during a map render without enabling a permanent drawing buffer. Uncapturable/cross-origin images fall back to URL and view context.

The `canalFeedback` collection lives in the existing default Firestore database in `map-recall2-blackmad`. Each note stores immutable user text, target/model, optional image anchor, bounded JPEG, camera/rendering/route context, host/origin, viewport/device, capture time, and `deployment.json` metadata. Arbitrary URL query parameters and a home destination are excluded. Feedback can still include the current game/map position. Browsers submit via Google auth and can read only their own notes. Browser edits, deletes, and work-status changes are denied. Queue workers use existing operator IAM access through `gcloud`; credentials never go into public files.

Pull with `npm run feedback:queue -- pull` (defaults to 50 open notes), then use [.agents/skills/canal-feedback/SKILL.md](../.agents/skills/canal-feedback/SKILL.md) for claiming, fixing, verifying, resolving, or deferring tasks. Snapshots and extracted images stay under ignored `.cache/canal-feedback/`; existing landmark and street queues remain separate. This skill processes work when invoked; it does not create a scheduled/background worker.

Build with `npm run build:canal-feedback` (also part of the normal site build). Google authorized domains must include the deployed host. Deploy `firestore.rules` when changing access rules. Validation: `npm run test:feedback`, `npx playwright test tests/e2e/feedback.spec.ts`, and `npm run test:feedback:rules` (requires Java for the demo-project Firestore emulator). The rules test explicitly refuses to run without `FIRESTORE_EMULATOR_HOST`.

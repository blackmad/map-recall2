# Start here: adding buildings to Ride Amsterdam

This is the entry point for anyone, person or agent, who wants to add or
improve buildings in the game. Read it in full first. It is short on purpose,
and it links to the deeper docs instead of repeating them.

Read these next, in this order:

1. [`CLAUDE.md`](../CLAUDE.md): working agreement, product principles,
   verification rules. Codex, Claude and other agents should all follow it.
2. This doc.
3. The section of [`buildings-pipeline.md`](buildings-pipeline.md) for your
   kind of work (see §2). Don't read the whole 1,500 lines.
4. [`LOOK.md`](LOOK.md) "Palette and saturation", if you choose colours.
5. One or two installed examples of your kind (named in §2). There are 300+
   builders; don't read them all.

---

## 1. Setup

```sh
git clone --filter=blob:none https://github.com/blackmad/map-recall2.git   # ~1 GB; full history is much larger
cd map-recall2
npm ci
npm run dev                          # tsx server.ts on PORT (default 3000)
```

- The ride is at <http://localhost:3000/canal-drive/>. The gallery pages below
  are served from the same server.
- If several agents work at once, give each its own git worktree, its own
  branch and its own port: `PORT=4450 npx tsx server.ts`. Playwright reuses
  any server already on its port, so set `PW_PORT=<your port>` for e2e runs.
- Stop your server by its port's PID:
  `kill $(lsof -t -iTCP:<port> -sTCP:LISTEN)`. Never `pkill` by pattern,
  because other agents' servers match the same pattern.
- Run one browser-heavy job at a time per machine. The maintainer's machine
  has a lock wrapper at `/tmp/canal-pw.sh`; if it exists, run Playwright and
  `review:sheet` through it (`bash /tmp/canal-pw.sh <command>`).
- If `git` misbehaves in your agent's shell on the maintainer's Mac, use
  `/usr/bin/git`. That's a local wrapper issue, not a repo rule.
- Raw API responses are cached under `.cache/` (untracked). Review output goes
  to `artifacts/` and `staging/`. Don't commit either unless a doc says so.

Before you start any building, check that nobody has done it already:

```sh
git log --oneline origin/main -i --grep "<building or street name>" | head
grep -n "<id or BAG pand>" src/canalRecall/landmarks/manualCatalogue.json | head
ls scripts/landmarks scripts/building-recipes/houses scripts/block-face/faces | grep -i "<name>"
```

Two models on one ground fail `npm run test:building-taxonomy`
(`modelOverlap.test.ts`).

## 2. The three kinds of building work

Every placed model is exactly one category: `landmark`, `ordinary` or
`street-survey` (typed in `src/canalRecall/buildingCategory.ts`). The work
splits into three tracks.

### A. Bespoke landmarks (hand-written builder → GLB)

For destinations and recognisable buildings: churches, museums, theatres,
stations, ornamented historic fronts.

- **Code:** `scripts/landmarks/<id>-builder.ts` with
  `<id>-spec.json`, `<id>-footprints.json`, `<id>-elevations.json` and
  `<id>-inventory.json`. Shared tools: `BuildingTools` in
  `scripts/landmarks/cultural-builders.ts`, footprint shells and roof planes
  in `scripts/landmarks/house-geometry.ts`.
- **Register:** an entry in `src/canalRecall/landmarks/manualCatalogue.json`,
  plus one dispatcher line in `scripts/landmarks/build-manual-landmarks.ts`.
- **Gallery:** `/canal-drive/manual-landmarks.html?only=<id>`.
- **Queue:** `public/canal-drive/landmark-backlog.json` (regenerated by
  `scripts/landmarks/build-poi-backlog.ts`), requests in
  `public/canal-drive/poi-work-queue.json`, dashboard
  `/canal-drive/landmark-queue.html`.
- **Examples:** `westerkerk-builder.ts`, `noorderkerk-builder.ts`,
  `europarking-marnixstraat-builder.ts`.
- **Budget:** < 40,000 triangles, < 500 KB, no textures. Every material has a
  `materialSlot` and a `tint`.
- **Full recipe:** [`deepseek-modeling-lanes.md`](deepseek-modeling-lanes.md)
  §B5 (step by step), [`buildings-pipeline.md`](buildings-pipeline.md)
  "Bespoke landmark lane" and "Acceptance checklist", and
  [`landmark-building-recipe.md`](landmark-building-recipe.md) §2–§7
  (research sources, the elevations format).

```sh
node --import tsx scripts/landmarks/landmark-brief.ts --pand=<16-digit BAG id> --id=<id>   # brief + inventory skeleton from panoramas
node --import tsx scripts/landmarks/build-manual-landmarks.ts --only=<id>                   # export the GLB
npm run audit:glb -- --id=<id>                 # hard gates, inventory, z-fight
npm run check:landmark-inventory -- --id=<id>
npm run check:manual-landmarks
npm run compare:facades -- --id=<id>           # openings per storey vs your elevations spec
npm run check:osm-under-models
npm run test:building-taxonomy
npm run review:sheet -- --id=<id> --inventory --port=<port>   # photo | matched render | overlay | IN GAME, per wall
```

### B. Large buildings (`kind: "large"` recipes on the 3DBAG shell)

For grid-fronted modern and civic buildings: schools, libraries, offices,
halls. It uses a facade system per wall group, on the 3DBAG LoD2.2 shell.

- **Code:** `scripts/building-recipes/houses/<id>/intent.json`, with the kit
  in `src/canalRecall/blockBuilding/` and `src/canalRecall/buildingRecipe/`.
- **Gallery:** `/canal-drive/manual-ordinary-buildings.html`.
- **Examples:** houses `oba-slotermeer`, `stadsloket-noord`,
  `politie-van-leijenberghlaan`, `amsterdams-lyceum`.
- **Budget:** ≤ 12k triangles.
- **Full recipe:** [`deepseek-modeling-lanes.md`](deepseek-modeling-lanes.md)
  §B6 and [`buildings-pipeline.md`](buildings-pipeline.md) "Large tier".

```sh
node --import tsx scripts/pand-reference/all-walls.ts --pand=<pand> --archive --min-len=8 --max=12   # wall photos
node --import tsx scripts/building-recipes/facts.ts --house=<id> --pand=<pand> --large
node --import tsx scripts/building-recipes/walls.ts --house=<id>          # which 3DBAG surfaces form which wall
node --import tsx scripts/building-recipes/measure.ts --house=<id> --write   # measured colour, glazing, windows, bays
node --import tsx scripts/building-recipes/large.ts --house=<id> --strict    # GLB + gates + contact sheet with likeness
npm run test:large-tier
node --import tsx scripts/building-recipes/install-large.ts --house=<id> --install
npm run check:stale-installs
```

If no street-facing wall has a usable panorama, stop and report "no
evidence". Don't build from a guess.

### C. Ordinary streets: block faces, house types, neighbourhoods

This is the work with the most leverage: one side of a street between two
cross streets, authored as one unit and compiled into one chunk GLB. It draws
on a shared library of house types that whole neighbourhoods reuse.

- **Code:** `scripts/block-face/faces/<face>/intent.json` (schema
  `src/canalRecall/blockFace/intent.ts`), with the type library in
  `scripts/block-face/types/<district>/<type>.json`. Per-house canal-house
  recipes (`kind: "canal-house"`) live in `scripts/building-recipes/houses/`.
- **Gallery:** `/canal-drive/street-surveys.html`.
- **Examples:** face `nassau-145-152` (the benchmark, see §3) and
  `clercq-236681`, and the `oud-west` type library.
- **Budget:** ≤ 3,000 triangles per front.
- **Full recipe:** [`buildings-pipeline.md`](buildings-pipeline.md)
  "Block-face authoring", "House types for street surveys", "Shared
  house-type library"; for whole neighbourhoods,
  [`buurt-generator-20261016.md`](buurt-generator-20261016.md).

```sh
node --import tsx scripts/block-face/intake.ts --face=<id> --street=<Street> --seed=<pand>   # rectified strip of the whole face
#   write scripts/block-face/faces/<id>/intent.json while looking at staging/block-face/<id>/strip-labelled.png
node --import tsx scripts/block-face/compile.ts --face=<id>             # chunk GLB + gates + interference (add --install on your branch)
node --import tsx scripts/block-face/review.ts --face=<id>              # photo | ortho model | 50 % overlay strip sheet
npm run test:block-face
PW_PORT=<port> npx playwright test tests/e2e/block-face.spec.ts --project=desktop --project=iphone
```

The current priority is kits and repeated buildings over one-off houses: a
type that fixes a hundred fronts beats one more bespoke house.

## 3. The acceptance bar

**Likeness to the photo is the bar. Passing gates is not.** Batches of
large-tier buildings that passed every gate were rejected as "awful", because
the photo showed dark brick and tall glazing and the model had tan brick with
punched windows. A wrong kit is worse than the plain 3DBAG box, and "do not
install" is a valid outcome.

- **Improve the kit; don't fit the nearest option.** When the photo shows
  something no component or system can express, add it in your change: typed,
  unit-tested, and byte-identical for every model that doesn't use it
  (`npm run test:building-recipes`; `fit-golden` must not move for other
  houses). Every report lists what the kit still cannot express.
- **Measure, don't guess.** Wall colour, glazing fraction, window shape and
  bay rhythm come from the rectified crop (`measure.ts`,
  `palette-from-strip.ts`). Take tints from sunlit crops; the city already
  reads too dark, so never darken a colour to make it "feel" historic.
- **Windows and white accents.** On canal houses, record the window kind,
  head shape and pane layout per storey, how storeys diminish upward, and
  the white accents: speklagen (white bands), arch rings, keystones, sills on
  consoles, quoins, eared surrounds, white frames. Review sheets show the
  window row against the photo.
- **The benchmark is Nassaukade 152–145** (`nassau-145-152`, write-up in
  [`nassaukade-506-20261014.md`](nassaukade-506-20261014.md)). It has narrow
  fronts painted near-black, brown and tan, continuous white bands at every
  lintel and sill, eared white surrounds with keystones, sash windows that
  diminish upward, timber balconies with turned white rails, a two-storey
  bay window and pediment dormers. Any change to the 1890s kit vocabulary is
  checked against this face's strip.
- **Roofs come from the front, not 3DBAG.** When a front has a measured
  crown, eaves line or parapet, generate the roof from it: a saddle under the
  crown, flat behind a parapet. Never put a roof plane above a measured crown
  (gate `roof-under-crown`). Use 3DBAG roofs only for rear wings and plain
  cornice fronts with no measurement.
- **Gables are symmetric.** Stepped, neck and bell gables are almost always
  symmetric. A lopsided gable means a 3DBAG plane above the crown, or a step
  count read off an occluded flank.
- **Rows are coherent.** In a run of three or more houses of one type built
  within ±2 years, clamp an unmeasured eaves or ridge more than 0.8 m off the
  row line to the line, unless the photo skyline confirms it. Print every
  clamp on the sheet.
- **Ornaments make the building.** For landmarks, inventory every relief,
  sculpture, crest, gable stone, sign, clock and canopy on every wall before
  writing geometry (`<id>-inventory.json`). "No component" is never a reason
  to skip one. The Hoofdbureau van Politie once shipped without its
  coat-of-arms relief because its brief was written from memory.
- **Never describe a building from memory.** Every feature comes from a
  photo or a cited source. A wall without a photo is labelled `inferred`.
- **Judge every wall, bay by bay.** "Recognisable from its best side" let
  blank walls through (Nassaukerk) and scattered windows on five identical
  bays (Het Pakhuis).
- **Review at gallery size, from all four sides.** Open the gallery card at
  full size and check that every part has a building behind it. Downscaled
  strips once hid a "door without a building" (Oudemanhuispoort). Then check
  the `review:sheet` IN GAME column from where riders pass.
- **Statues are not kit work.** Sculptures go to the reconstruction or
  impostor track ([`sculptures.md`](sculptures.md)), never primitive kits.
- **Uncertainty is a hold.** Anything you list as uncertain blocks the
  install. Never weaken a check: no raised baselines, loosened thresholds or
  allowlist entries to get green.

Geometry rules that gates enforce: metres, native scale 1; trim at least
5 cm off the wall (10 cm for roof sheets) or set into a cut hole, never flush
and never 2–3 cm proud (z-fighting; a new export may carry at most 0.5 m²);
windows on a real wall, never across a corner; roofs face up and meet their
supports; courtyards, holes, underpasses and passages stay open; never pad a
footprint into a rectangle that hides a neighbour.

### Open data only

Use the Amsterdam panorama API (CC BY 4.0), BAG (CC0), 3DBAG (CC BY 4.0),
AHN, BGT, the RCE monument register (CC0), the Stadsarchief Beeldbank (rights
per record), OSM, and Wikipedia/Wikimedia Commons (licence recorded).
**Never** use Google or Apple imagery, Street View, Earth or photorealistic 3D
tiles, even as a quick reference for a model. Never copy a third-party mesh,
and never put photo pixels on a model. The house style is texture-free flat
colour. Source details:
[`research/amsterdam-open-sources-20261009.md`](research/amsterdam-open-sources-20261009.md).

## 4. Landmark integration rules

A modelled landmark is part of three game surfaces, and is not complete until
all three are audited together:

1. a selectable route destination;
2. a geographically correct map pin and label;
3. a meaningful info card with research source links.

Reuse genuine extract identities. Parts of one complex share one POI; don't
manufacture duplicate destinations for aliases or mesh parts. A selected
destination never silently becomes another POI when it can't be reached.
Year-built-only metadata is not trivia: clicking such a building selects
nothing.

**Suppression.** A model hides the exact OSM/BAG identities it replaces
(`suppressOsmIds`), only after its GLB loads, and the fallback returns if
loading fails. That covers every ordinary building layer, including the
pyramidal-roof renderer. Neighbours stay visible: no padded rectangular
suppression. When a new model replaces an older one on the same ground, set
the old entry to `status: "held"` with a `heldReason`, or add it to
`SHADOWED_BY_LANDMARK` in `src/canalRecall/landmarks/ordinaryModels.ts`, in
the same commit.

**Signage.** Don't paint building names on for identification; the map
label names the POI. Model a real sign only when it is a defining
architectural feature. Fit it to its real panel and wall plane, and match
the lettering's family, weight and proportions as closely as geometry allows.
Record an approximate font match when the typeface is unknown.

**Research.** For a historic landmark, make one bounded address search in the
Stadsarchief Beeldbank and read its monument-register description early.
Compare dated drawings with current photos.
[`landmark-building-recipe.md`](landmark-building-recipe.md) §3 lists the
sources.

## 5. Source archiving

Every model keeps its evidence: original panorama crops, register pages,
survey and API responses, with provenance and dates.

- **Maintainers** archive per model id into the private companion repository
  `blackmad/map-recall2-source-data`:
  `python3 scripts/landmarks/archive-model-sources.py --only <id> --verify --destination <source-data worktree>`
  (gzip any file over 95 MB). See
  [`landmark-building-recipe.md`](landmark-building-recipe.md) "Archive every
  source".
- **Outside contributors** without access: keep the sources under
  `artifacts/` (untracked), and list every panorama id, URL and licence in
  your report so the maintainer can archive them.

Record panorama ids and source URLs in the intent's `sources[]` / `notes[]`,
or in the brief, so the evidence survives even if the crops don't.

## 6. What you may edit, and how to hand back

**You may edit:** your own builder, spec, footprint, elevations, inventory and
brief files under `scripts/landmarks/`; your houses, faces and types under
`scripts/building-recipes/houses/` and `scripts/block-face/`; the kit modules
your building needs (`src/canalRecall/blockBuilding/`,
`src/canalRecall/blockFace/`, `src/canalRecall/buildingRecipe/`,
`src/canalRecall/landmarks/`), each with a test; your entry in
`manualCatalogue.json` and one dispatcher line; the model outputs the build
writes for your id.

**The integrator owns these; don't edit them, ask instead:**
`public/canal-drive/TODO.md`, `public/canal-drive/HISTORY.md`,
`package.json` and lockfiles, `public/canal-drive/game.js`,
`public/canal-drive/index.html`, generated bundles
(`public/canal-drive/js/*.bundle.js`), `public/canal-drive/models/covers.json`,
and the baselines and goldens (`scripts/landmarks/geometry-audit-baseline.json`,
`scripts/building-recipes/fit-golden.json`, `large-mesh-golden.json`). If a
check needs one regenerated, put the exact command in your report.

**Hand back** a branch, a commit SHA and this report:

```
BRANCH: <branch>    HEAD: <SHA>    KIND: landmark | large | block-face/type    ITEM: <id / name>
OUTCOME: ready to install | held (why) | do not install (why) | blocked (why)
FILES: <new/changed files>
IDENTITY: pand ids replaced, OSM ways suppressed, neighbour kept visible
SOURCES: panorama ids + dates, URLs with licence
NUMBERS: triangles, GLB KB; z-fight m² before -> after; likeness per wall group
GATES: <command -> summary line, one per line>
SHEETS: paths to review sheets / contact sheets / gallery views from four sides
INFERRED: walls or parts with no photo evidence
KIT CANNOT YET EXPRESS: <list>
UNCERTAIN: <list; each one is a hold>
INTEGRATOR TODO: covers rebuild, bundle rebuilds, baseline changes, etc.
```

Report failures as failures. "Gate X still fails at Y m²" is useful.

**After an install, the integrator** rebuilds covers
(`npx tsx scripts/build-covers.ts`, copy `artifacts/bag-tiles/covers.json` to
`public/canal-drive/models/covers.json`, then `npm run check:covers`). They
rebuild the signature bundle if suppression or material overrides changed
(`npm run check:signature-bundle`), and the landmark LODs for a new GLB
(`npm run build:landmark-lods`, `npm run check:landmark-lods`). For block
faces they also run
`npx tsx scripts/look/build-chunk-wall-exposure.ts --write`. Then they run
`npm run check:canal` and update TODO/HISTORY.

## 7. Pitfalls earlier lanes hit

- **Fitting the nearest kit option** instead of extending the kit (§3).
- **Writing a brief from memory**, which missed the signature ornament.
- **3DBAG roofs above a crown, and lopsided gables:** the user's most
  repeated corrections.
- **Too dark.** Measured tints from overcast panoramas read dour; use sunlit
  crops.
- **Two models on one ground:** hold or shadow the old one in the same
  commit.
- **Treating gates or aerial strips as acceptance.** Look at the gallery card
  and the IN GAME frame.
- **Hand-merging generated files.** On a conflict in goldens, `covers.json` or
  bundles, take one side and regenerate. Never hand-edit them.
- **A shell timeout shorter than the job.** Surveys, builds and sheet runs
  take minutes, so give long-running commands a long timeout instead of
  polling in the background.

The living references are [`buildings-pipeline.md`](buildings-pipeline.md)
(pipeline, schemas, gates, measured results) and [`LOOK.md`](LOOK.md) (art
direction). [`README.md`](README.md) indexes the rest of `docs/`.

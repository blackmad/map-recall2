## What round one measured (main at b52f002e0, HISTORY "Engine round 1")

- The S3 moiré is **not the swap**: `tests/e2e/swap-zfight.spec.ts` at `s3-slab` measures a still pan with no swap at all flipping **27,639 px at ΔE>20 over 24 steps of 0.35 px** (desktop DPR 1). That is texture and edge aliasing on the slab's façade. The swap's own contribution is 0 px on desktop since #223.
- The S2 fuzz is **not texel density**: 512 px cells measured no sharpness gain at S2 (`look/sharpness.ts` lapVar 757 vs 736 at `da-costakade-near`) for +260 MB, so `HIGH_CELL_PX` is pinned to 256 (`look/texturePolicy.ts:53`). #224's lead: the façade tier falling back to the mean colour earlier than intended, or the governor stepping the pixel ratio down. Unverified.
- Windows exist **only as painted pixels**. The bay looks (`src/canalRecall/bayTextures.ts`, canvas `BAY_PX` 520 × `STOREY_PX` 310, scaled to the 256 px slot in `look/paintLookAtlas.ts:153`) paint reveal, lintel, sill, a 5–16 px frame inset (`windowAt`, `:150-222`) and muntins by `sash` (`:207-220`). The older procedural cells (`facadeCells.ts paintWindow`, `:203`, frame 0.07 m) do the same. Nothing in any façade shader is analytic today (no brick, bands, shutters or frames in GLSL).
- A slot **is** a descriptor: `bayLook.ts bayLayer(archetype, style, kind)` (`:111`) maps to a `BayVariant` (`bayTextures.ts:27-49`: `windows 1|2|3`, `shape`, `lintel`, `sash`, `openingOccupancy`, `openingHeight`, `frameTone`, `shutters`…), and `bayWindowGeometry`/`layoutWindows`/`canalGroundGeometry` (`:433`, `:438`, `:225`) give the rect fractions the painter uses. So the shader can be told, per layer, where the windows are without any per-building data.
- Shader plumbing: the chunk carries `uv` in bay/storey units (repeating; `threeBuildingMesh.ts:534`, `:738-739`), `layer` (Uint8 slot, `flat vLayer`), `tint`, `accent`, `hidden`, `swapSlot` (`threeBuildingsBrowser.ts:1447-1457`). The tier sample is `roofTier.ts FACADE_TIER_GLSL` (`:96-112`): `rho` from `dFdx/dFdy × textureSize`, `far = smoothstep(cellTier.x, cellTier.y, rho)` with `FACADE_TIER_FROM_TEXELS 16 / TO 30` scaled by DPR × cellPx/256 (`facadeTierUniform`, `:62`; `setCellTierPixelRatio` `threeBuildingsBrowser.ts:1789`), mean via `textureLod(…, CELL_MEAN_LOD 12.0)`, and `far = max(far, DEPTH_FADE_DETAIL)` from 250 m (`look/depthFade.ts:44-46`). Materials in order of use: `look/cityLook.ts createCityLookMaterial` (`:655`, `FRAGMENT_CELL` `:546-558`, variant table `CityVariant` `:341-378`, `cityProgramKey` `:385`; lit chunk programs are `city-look-v4|lit|chunk[|swap]`), `rendererShared/litFacadeMaterial.ts` (`:68`, `:130`), raw `FRAGMENT` (`threeBuildingsBrowser.ts:140-177`). `ownGround/railStripes.ts` (`railStripeGlsl` `:68`, own program-key suffix) is the model for a flag-gated GLSL injection.

## Do, in this order, each behind a flag and measured

1. **Find the S2 owner before drawing anything.** At `da-costakade` and `da-costakade-near` (`scripts/look/crispSpots.ts`) at DPR 2 with `?perfHud=1`, record tier and pixel ratio, then add a debug variant `?cellDebug=rho` that paints `rho` (and `far`) as colour so a frame shows, per façade pixel, whether it is magnified (rho < 1), mip-blended (1–4), or flattened (`far` > 0). Post a histogram over the façade band on #228. Three outcomes, three fixes: `far` > 0 at the chase distance → the tier thresholds or `cellTierFollow` are wrong, fix that first (cheap, `?cellTierFix=0`), re-measure, and SDF windows are then about S3 only; rho < 1 → magnification blur, SDF windows are the fix; rho 1–4 → trilinear blur, SDF windows fix the frames and the brick stays as it is. Also check that the governor is not at the 0.75× floor on the user's profile (`__canalPerf.tier`, `renderGovernor.ts`).
2. **Per-layer window table** (`src/canalRecall/look/windowTable.ts`, typed, tested): for every atlas layer (`lookAtlasLayers`, ≤ 256) derive from the same `bayWindowGeometry`/`layoutWindows`/`canalGroundGeometry`/`bayDoorGeometry` calls the painter uses: window count and axes, opening rect fractions (x0, x1, y0 sill, y1 head), frame inset as a fraction, `shape` (rect / segmental / arch / round), `lintel`, sill depth, muntin pattern code from `sash`, frame tone and glass tone. Door, shop and plain cells get "no analytic windows". Pack it as a small `DataTexture` (N × 4 RGBA float or half; `texelFetch` by `vLayer`), not a uniform array (iOS fragment-uniform limits). The test asserts that the table's rects coincide with the painter's rects within one 256-px texel for every layer (paint the layer, threshold the mask's G accent channel, compare bounds).
3. **Analytic window in the fragment shader** (`?windowSdf=0` off, byte-identical by construction: the define is absent, program key unchanged, no table upload). Inject into `FRAGMENT_CELL` (and the lit material's `cellTierSample` call) under `CITY_WINDOW_SDF`, with its own program-key suffix like `-rails`; precompile via `SharedFrame.compileAsync` so `inFrameShaderLinksAfterWarmup` stays 0. In-cell uv is `fract(vFacUv)` for upper storeys (ground cells are `GROUND_PX`/`STOREY_PX` taller; handle the ground kind from the table). For each window of the layer: a rounded-rect / arch SDF for the opening, a second for the glass inside the frame inset, `fwidth`-based anti-aliasing, muntins as thin bars; the painted texel supplies wall, brick and reveal shading, the SDF supplies frame, glass and sill where it says "window". Blend the analytic result out with the same `far` the tier sample uses, so the mean-colour fallback and the depth fade are unchanged (below ~2 px per cell the SDF is pure cost). Keep `accent`, `tint`, `cityFade`, the CITY_SWAP complement and the toon post pass working. Touch tier: on by default only if step 5's iPhone GPU number holds; otherwise off on touch and say so.
4. **Pin S3**: `swap-zfight.spec.ts` already measures the still-pan ΔE>20 area; run it with `ZFIGHT_QS=windowSdf=0` and default at `s3-slab` (desktop DPR 1 and DPR 2, iPhone profile). Target: still-pan area down ≥ 80 % (27,639 → ≤ 5,500 px at DPR 1) with the swap excess still 0. Add a `stillPanPxS3` row proposal for `budgets.json` with both numbers.
5. **Pin S2 and the cost**: `tests/e2e/crisp-textures.spec.ts` (`CRISP=1`, `CRISP_VARIANTS="before=windowSdf=0;after="`) at `da-costakade`, `da-costakade-near`, `da-costakade-chase`, plus `westerkerk` and `dam` from `AB_SPOTS` for GPU ms. Sharpness (lapVar, edge, acutance) in the façade band must rise at the S2 spots; GPU ms ≤ +1.0 ms at Dam/Westerkerk on desktop and ≤ +2.0 ms on the iPhone profile, as the **median of 5 runs** (the timer query swings ±2–3 ms run to run; one run proves nothing). Facade texture MB unchanged (the table is < 64 KB).
6. **Strips**: user shot | flags off | flags on at S2 (chase distance, DPR 2) and S3 (150 m, mid-pan), desktop and iPhone, with 4× crops of one bay so the frame edge is visible; `look-consistency` and `three-buildings-ab` pixel-identical with the flag off.

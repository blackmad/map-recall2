Reading:

- **Map render p50 did not regress** (A 3.3 vs B 4.1–4.2, inside noise, A
  better); p95 is 3 ms worse in A (10.1–10.3 vs 7.1–7.3) and sits on the 10 ms
  budget line.
- **The label overlay cost per frame roughly tripled**: 514–532 ms over ~720
  frames (mean ≈ 0.71–0.73 ms) against 137–156 ms (≈ 0.20 ms) before the
  gameplay lanes; worst frame 15–24 ms vs 4–10. `DESKTOP_BUDGET.labelFrameMeanMs`
  is 0.4 and now fails. Candidates, by what landed in the label path: L1's
  label-draw ledger (`labelDrawLedger.ts`, a record per label per frame plus the
  30 s / 60 s withheld rules) and the per-frame withheld-name screening
  (`landmarkWithheldNames`, `landmarkDisplayName`) added by L1/L3; L5's
  `withDisplayNames` runs once at load and is not a candidate.
- **No new frames over 100 ms** in either run; motion stutter equal within noise.
- The iPhone project (4× throttle) passed all four variants: frames median 16.7,
  p95 33.3, over 100 = 0 (default, landmarks off, repeat) and 2 (all landmarks
  resident, as before); map render median 11.1–12.0.
- `scripts/perf-gate.mjs ""` ran but printed `n/a` for every row (its collectors
  found no artifacts; see TODO).

Decision: P1 lane "label overlay back under 0.4 ms mean" with this table as the
acceptance bar (A/B by `BUNDLES_DIR`, same method), before the P2 gameplay
follow-ups. Budgets unchanged.

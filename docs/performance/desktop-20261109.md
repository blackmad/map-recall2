The profile (`PERF_PROFILE=1` plus the new opt-in `PERF_LABEL_SPLIT=1`) placed the
cost in `startPlan`, the per-candidate `labelAllowed` → `hiddenNames.some(containsAskedName)`
screen NFD-normalising ~5,676 candidates against each withheld name on every 250 ms
plan (629–645 ms of 658–677); the ledger write (`finishPlan`) was 4 ms in total. So
the issue's first guess (the ledger) was wrong and the plan, ledger and rules run per
plan, not per frame. After: the verdict is memoised per candidate and reset when the
rules' inputs change, `withheldNames` returns one frozen array per withheld set, asked
names are normalised once per array, the ledger takes pre-made keys and skips an
unchanged set. Both default variants pass `DESKTOP_BUDGET`. Open: on the seeded chase
route `labelStats` reads candidates 5676, inView 0, drawn 0 in every run, so ride-perf
measures the screen only and the default ride draws no POI labels there (check whether

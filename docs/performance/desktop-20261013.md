# Desktop ride performance after the 2026-10-13 merges

Desktop perf lane, 2026-10-13. Nobody had profiled the whole ride since the
day's merges (fixed sun, mood pass, roof/facade tiers, 105,646 sheds, roof
furniture, the POI label DOM overlay, the highlight marker, own-ground cells,
the HUD tuck, labels `hitTest`), each of which reported "within noise" alone.
This is the whole ride, by owner, on desktop. The iPhone profile is
**pending** (not measured here; desktop is ~10x the priority).

## Budget (desktop 1440x900, chase, fixed route)

Anne Frank Huis -> Rijksmuseum, car, chase view, seeded `Math.random`, 12 s
holding ArrowUp after the city settles. Frame times are **uncapped**
(`--disable-gpu-vsync --disable-frame-rate-limit`), so a frame interval is
what the frame cost, not the display cadence; "owned" is the main-thread time
inside wrapped owners. Owner columns are the mean of two wrapped runs; frame

frame now take up to 3 ms (plus one pick) in each of a few frames.

## Where a frame goes (before)

Exclusive main-thread ms per frame, by owner (`scripts/ride-perf-owners.mjs`:
every prototype method of the game, HUD, camera, track, vector map and each
render component is wrapped with a stack timer; MapLibre custom layers by id;
MapLibre's own `_render` is what remains after the layers and `render`
listeners it calls):

- **MapLibre** 1.1-1.9 ms: its own tile/symbol/fill work. Untouched here.
- **three.js layers** 1.0-1.7 ms: the bike 0.4-0.8 (two passes, x-ray then
  normal; the per-frame sun re-aim is two `enuDirectionInLocal` calls and does
  not register), signature landmarks 0.4-1.1, pyramidal roofs 0.16-0.4, facades
  0.12-0.24, trees 0.05-0.1; with own ground the shared frame's pass is
  2.1 ms. Three.js scene traversal (`updateMatrixWorld`, `projectObject`) is
  the largest part of the profile under these.
- **Label overlay** 0.7-1.2 ms: almost all `map.getStyle()` in its per-frame
  guard (a deep copy of the whole style; 1.4 s of self time per 12 s window
  in MapLibre's clone function, plus the garbage). Fixed (1).
- **HUD canvas** 0.5-1.0 ms (street names 0.4-1.3 of it): `RoadNetwork.drawLabels` walks all 28,931 street
  label anchors every frame; 4,239 are within reach of the chase camera and
  get the knowledge test, 24 are on screen, none are drawn for a guest. A
  grid index was tried and measured no better (the ascending sort it needs
  ate the gain; aerial got worse), so it was reverted. Next candidate.
- **Signature landmarks CPU** 0.24-0.48 ms: `map.getBounds()` once per model per
  `moveend` (every frame) and per entry in render/LOD/picking. Fixed (3).
- **Game update, camera, vector-map sync** ~0.6 ms together; `_updateRiderCover`
  still calls `getStyle()` per frame (0.05-0.16 ms; it lives in `vector-map.js`).
- **GC** 2 % of the CPU profile (0.12 ms/frame), largely the style copies.
- Highlight marker: not drawn on this route by default (`?highlight` unset).
  HUD tuck `mousemove`: passive, four assignments; not exercised by a keyboard
  ride and not a cost. Three-buildings worker and own-ground cells: no chunk or
  cell installs inside the 12 s window once the city has settled (buffer uploads
  2.4-4.1 MB per 12 s, texture uploads 22-38).

## Long frames (> 33 ms) and their cause

| config | before | cause | after |
|---|---|---|---|
| default chase | 0 (frames are 5-9 ms) | -- | 0 |
| `?ownGround=1` | 0-5 per 12 s | label plan: 40 occlusion picks in one frame (landmarks 7-24 ms + city prism picks 8-13 ms + plan 6-8 ms) | 0 |
| `?sharedFrame=1&cityLook=1` | 0-3 per 12 s | label plan, as above (landmarks 19-24 ms) | 0 |
| aerial hold 300 m | 47 / 47 per 12 s on a loaded machine (every plan, 4 a second, 42-45 ms), 0-3 when the machine was quieter | label plan: `landmarks.inspectAtScreen` ~20 ms (three.js `Raycaster` against every visible landmark mesh, no BVH), the city's prism picks ~7 ms, the plan itself ~7 ms (5,677 candidates projected, HUD rects, label sizes) | 1 per 12 s: a MapLibre tile batch (20-26 texture uploads, 2-2.6 MB of buffers) whose frame owns only ~5 ms of script, so the stall is GPU-side upload |

Not seen in any window: chunk compiles (0 program links in the default, shared
and aerial runs; 1 in own ground, at cell load), shadow-map redraw spikes,
label replans outside the plan, cell loads (they finish before measuring;
cell-load latency is in the own-ground lane's numbers).

## The three fixes (by measured ms)

Each is its own commit with its before/after in the message; base/fix runs
interleaved, two each.

1. **Labels: no `getStyle()` per frame** (`labelOverlay.ts`, `styleReady()`
   reads `style._loaded`). Label owner 1.18 -> 0.09 ms/frame; frame median
   6.5/6.4 -> 5.6/5.6 ms; owned 6.4 -> 5.4 ms/frame; GC 0.116 -> 0.071
   ms/frame. Nothing drawn changes (labels.spec counts identical).
2. **Labels: occlusion picks spread over frames** (`labelOverlay.ts`,
   `startPlan` / `stepPlan` / `finishPlan`, 3 ms per frame, at least one pick,
   each pick against the current camera). Aerial hold: frames > 33 ms 49/47 ->
   2/1, p99 37.7/42.4 -> 17.4/15.7 ms, landmarks worst frame 18.8/20.8 ->
   11.4/7.9 ms; chase: landmarks worst frame 17.5/19.0 -> 8.0/7.8 ms. Same
   verdicts, hysteresis, order and 40-pick cap; a plan completes 2-8 frames
   after it starts, inside the 250 ms interval. labels.spec counts identical.
3. **Signature landmarks: view bounds once per camera change**
   (`signature-landmarks-source.js`, `_viewBounds()`, dropped on `move`,
   `resize`, `render`). Landmarks owner 0.48/0.32 -> 0.16/0.16 ms/frame,
   `_requestModels` 0.33/0.22 -> 0.08, frame median 5.1/4.4 -> 4.2/4.0 ms.
   Same culling and load order.

No fix changes what the game shows (no LOD, budget or tier change).

**Bundles the integrator must rebuild:** `orientation-pois.bundle.js`
(`npm run build:canal-orientation-pois`, fixes 1-2) and
`signature-landmarks.bundle.js` (`node scripts/build-3d-bundles.mjs
--only=signature-landmarks`, fix 3). Until then the committed bundles run the
old code and the spec's label budget fails (measure the new code with
`BUNDLES_DIR=<dir>`).

## Ride-perf spec

`tests/e2e/ride-perf.spec.ts` now also times the label overlay's frame
handler, accepts `BUNDLES_DIR`, and pins `DESKTOP_BUDGET` for the two
`default` variants on the desktop project: map render median <= 6 ms and
p95 <= 12 ms, label overlay mean <= 0.6 ms and worst <= 30 ms, frames over
100 ms <= 2. Before the fixes it fails on the label mean (0.91 and 1.23 ms);
after, 4 passed (label mean 0.26-0.42 ms). Budgets are main-thread ms, not
frame intervals: the interval is the display cadence whenever a frame fits,
and this machine's headless Chrome ran at 30 Hz while its display slept and
60 Hz when awake.

## Next, measured but not fixed

- HUD street names (`drawLabels`): 0.5-1.3 ms/frame for zero drawn labels for
  a guest. A per-name index of the knowledge test or skipping the walk when
  nothing is known would be the fix; it needs `game-presentation`/`road-network`
  care to keep the draw order (overlap winners).
- Landmark picking: `inspectAtScreen` raycasts every visible landmark mesh
  triangle by triangle (~0.5-0.7 ms per pick); a bounding-box pre-test per
  entry or a BVH would cut the label plan and click picks.
- `vector-map.js` `_updateRiderCover` calls `getStyle()` per frame
  (0.05-0.16 ms + garbage); a two-line change for the integrator.
- three.js scene traversal per frame for landmark scenes (matrix updates on
  static models: `matrixAutoUpdate = false` after placement).
- The bike layer draws the model twice per frame (x-ray + normal), 0.4 ms.
- iPhone 13 (4x throttle) profile of the same four configurations: pending.

## Reproduce

```sh
PORT=4465 npm run dev   # this checkout
# per-owner profile, four configs (uncapped frames; NO_WRAP=1 for clean frame times,
# NO_PROFILE=1 to skip the CPU profile, TRACE=1 for a 4 s timeline trace,
# BUNDLES_DIR=<dir> to serve locally built bundles):
export PORT=4465 CHROME_ARGS="--disable-gpu-vsync --disable-frame-rate-limit"
node scripts/ride-perf-owners.mjs default "" chase 12
node scripts/ride-perf-owners.mjs ownground "?ownGround=1" chase 12
node scripts/ride-perf-owners.mjs shared "?sharedFrame=1&cityLook=1" chase 12
node scripts/ride-perf-owners.mjs aerial "" aerial 12
# pinned budget:
PERF_RIDE=1 PW_PORT=4465 npx playwright test ride-perf --project=desktop
```

Results land in `artifacts/perf-owners/<label>.json` (owners, top methods,
long frames with their owners, GL work and long-animation-frame entry, hot
functions, GC). Chrome 155 headless on an Apple M4 Pro (ANGLE/Metal).

## The four fixes (one commit each, before/after in the message)

1. **HUD street names: per-cell candidate list, no walk when nothing can
   draw** (`src/canalRecall/game/streetLabelCandidates.ts`, used by
   `presentationRuntime.ts`; `road-network.js` `drawLabels` takes it as an
   optional sixth argument). A label can only pass the game's knowledge test if
   its name is in `_mapLabelNames` or `_knownPlaces`; when both are empty (a
   guest) the walk is skipped, otherwise the anchors of those names within
   reach of the camera's 256-unit cell are cached in anchor order until the
   cell, reach bucket or name set changes, and `drawLabels` still applies all
   its own tests to them (unit test: equal to the full walk, in order, over
   400 random cameras). `track.drawLabels` 0.51 / 0.54 -> 0.01 / 0.01 ms per
   frame in chase. The earlier grid index lost to its ascending sort; this one
   sorts only when the name set changes.
2. **Landmark picks: bounding-box pre-test per model, per-mesh BVH built in
   idle time** (`src/canalRecall/landmarks/pickBvh.ts`,
   `signature-landmarks-source.js`). The cost was not misses but hits and
   near-misses on big models (Pulitzer 39k triangles, Westerkerk 21k: three's
   Raycaster tests every triangle once inside a mesh's box and builds a full
   record per crossing). `nearestVisibleHit` returns what
   `intersectObject(group, true).find(visible)` returned (unit test, 2,400
   rays over mirrored/grouped/draw-ranged/mixed-side/instanced/hidden meshes);
   a pick never builds a BVH, it queues the model for idle time (forced after
   250 ms for at most 3 ms). In-page bench, 360 picks on a 24x15 grid in the
   aerial hold: 0.17-0.21 -> 0.013-0.022 ms per pick, identical id and depth at
   every point. `landmarks.inspectAtScreen` 0.21 / 0.19 -> 0.01 / 0.01 ms per
   frame aerial, worst call 6-7 -> 1 ms.
3. **Landmarks: compose placed models' matrices once**
   (`src/canalRecall/landmarks/staticMatrices.ts`). `matrixAutoUpdate =
   false` on every placed model (and its legacy scene and lights) after
   placement and on a swapped-in level; legacy model scenes also stop the
   per-render `updateMatrixWorld` walk and are refreshed where their contents
   change (level swap, highlight passes). CPU profile, chase:
   `updateMatrixWorld` inclusive 129 / 112 -> 46 / 58 us per frame
   (the rest is the bike, roofs, facades and trees); aerial: matrix work
   ~200 us per frame -> under the 30 us listing floor. Within noise on the
   wrapped layer owner.
4. **Bike: the x-ray and the model in one render**
   (`player-vehicles-source.js`). Why twice: the layer rendered the scene once
   with the x-ray override material (yellow, `GreaterDepth`, no depth write) and
   once normally; each render is a full three.js pass, and the override was
   transparent and double-sided, so three also split it into back and front
   draws. Now each mesh has an x-ray twin (shared geometry and material, made
   opaque-list with `CustomBlending` set to three's straight-alpha
   NormalBlending factors) that sorts ahead of the opaque model by
   `renderOrder`: the same x-ray-then-model order in one render. Committed
   bundle vs this, six frozen frames with the bike pushed into the blocks
   ahead (x-ray showing through a building): 0 pixels differ by more than
   30/765, identical yellow counts. Bike layer 0.27 / 0.29 -> 0.07 / 0.08 ms
   per frame; draw calls 466 -> 448 median.

## Method change: in-page A/B

The machine was shared with other lanes all night (load average 3-19 on 14
cores, swinging within minutes), and separate runs drifted by 20-30 % in
owners no fix touched (game, HUD, track): an "after" run could be slower than
its "before" twin on every row. So each fix also has a runtime switch, and
`ride-perf-owners.mjs AB_ON='<js>' AB_OFF='<js>'` flips it every 500 ms
through the same 12 s window, tagging every frame with the mode in force
(the frame after a switch is left out). Before and after then share the page,
the route and the machine's state; the untouched owners agree to within
0.05 ms, which is the check that the comparison is fair. The switches:
`_signatureLandmarks.setLegacyBatch(on)`, `_pyramidalRoofs.setBatch(on)`,
`_playerBike.setXrayTwins(on)`, `window.__canalRecallPrismGrid`, and for
`vector-map.js` the old file served (`OVERRIDES`) with `map.jumpTo` wrapped by
the zoom hold and the casing's visibility toggled. Pixel checks use the same
switches on frozen frames (`scripts/perf-frozen-frames.mjs`: the rider is
teleported, streaming waits until idle, the game's camera sync is frozen and
MapLibre's canvas is read inside its `render` event; frames on / off / on
again, the last pair being the noise floor).

(Single-fix A/Bs ran at different times of the night, so their absolute
levels differ; compare within a row.)

1. **Legacy signature landmarks: every model in one scene**
   (`src/canalRecall/landmarks/batchedLegacyFrame.ts`,
   `signature-landmarks-source.js`). The layer gave each placed model its own
   `THREE.Scene` (with its own copies of the three lights) and its own
   `renderer.render`, baking the model's Mercator transform into the camera:
   up to 131 renders a frame in the aerial hold, each redoing three's light
   setup, render-list build and sort. Now each model is a holder in one scene
   whose world is metres about an anchor laid out like glTF (x east, y up,
   z south), re-based when the view centre is 1.5 km away. The camera's
   projection is MapLibre's matrix × `mercatorFromWorld` and a holder's matrix
   is `worldFromMercator × transform`, both composed in doubles, so a vertex
   sees the old projection × transform. One light set is aimed through the
   anchor with the same `enuDirectionInLocal` the per-model copies used; the
   recipe look's `enuFromWorld` comes from the anchor; a custom sort keeps the
   old model-by-model draw order with three's own painter order inside a
   model. Highlight passes (`hlEye`, roof-wash `up` = +y), `canShowModel`
   suppression and picks (one clip-from-world for every model) are unchanged.
   Not under `?cityLook=1` in the legacy layer: its tier distance is measured
   from the per-model eye at the model origin. `?landmarkBatch=0` keeps the old
   path. Unit tests: projection × holder equals projection × transform to
   1e-9 over 200 random placements (both placement branches), n·l of the one
   light set equals the per-model lights' (exact for the bearing branch, within
   3e-3 for the near-orthogonal RD basis), the recipe ENU maps normals the same,
   and the sequence sort reproduces three's order inside each model.
   Frozen frames: 85-245 of 1.3 M pixels differ by more than 30/765 (noise
   floor 0-32), all z-fight speckle along coplanar faces: a different
   factorisation of the same matrix rounds differently in float32, and a
   coplanar tie can flip. No visible change (crop compared at 4x).
2. **Shared frame: the vehicle x-ray as twins** (`player-vehicles-source.js`).
   Under `?sharedFrame=1` the vehicles still handed the frame an
   `xrayMaterial`, so its overlay pass rendered the whole shared scene once
   more per vehicle with the transparent override (which three splits into
   back and front draws on a double-sided material), and each extra render
   also walks every participant's matrices. Pass two's twins (opaque list,
   straight-alpha `CustomBlending`, `renderOrder` -1e6) now go into the
   vehicle's root there too and `xrayMaterial()` returns null: one overlay
   render. Frozen frames with the rider behind the Royal Palace (x-ray
   showing): 666 vs 671 yellow pixels, 68 px > 30 on/off against a noise floor
   of 83; Dam and Westerkerk at the floor.
3. **City prism picks: a grid per chunk** (`src/canalRecall/prismPick.ts`
   `buildPrismGrid` / `pickPrismGrid`, used by `threeBuildingsBrowser.ts`).
   The label overlay's occlusion picks ran `pickPrism`'s slab test on every
   building of every chunk whose bounding sphere the ray crossed. The grid
   buckets each prism's plan box (+0.5 m) into 32 m cells; a pick walks only
   the cells the ray crosses while it is inside the chunk's (own-ground
   lifted) height range and runs `pickPrism`'s loop on those candidates in
   index order, so the hit is the same entry and t, ties to the earlier entry
   (unit test: 3 × 4,000 rays, aerial, grazing, vertical, axis-aligned and
   arbitrary, random lifts and skips, exact equality). The lift range per
   chunk is cached by applied size and hidden revision.
4. **MapLibre: hold sub-1e-6 zoom jitter; hide the empty highlight casing**
   (`vector-map.js`, 4 lines). See the MapLibre section below. The game's
   camera zoom moved by ~1e-8 every frame (`cos(lat)` and float noise), so
   `jumpTo` fired `zoom` and MapLibre re-evaluated the whole style every frame
   (180 style updates in 180 frames with the rider stopped; 3 after). `sync`
   now keeps the map's zoom when the new one differs by less than 1e-6
   (0.0005 px at the screen edge). The casing layer's opacity is 0 for every
   feature but the accent one, yet it drew every building outline on every
   tile; it now starts hidden and `setActiveLandmark` shows it only while an
   accent target is set. Pixels: the casing toggle is at the noise floor; a
   1.7e-8 zoom step (one frame of the old jitter) re-rasterises 2,458-6,575
   edge pixels of a frozen frame, as many as the hold's worst case
   (1e-6: 4,045-12,572), so the hold removes a per-frame shimmer rather than
   adding a change.
5. **Legacy pyramidal roofs: one scene, one render**
   (`pyramidal-roofs-source.js`; not in the brief, found in the owner table:
   it cost more than the landmarks in chase). Same construction as fix 1,
   unlit, so no light aiming. `setBatch(false)` keeps one render per cap.
   Frozen frames (Waag, Dam, Dam aerial) at the noise floor.

**Bundles the integrator must rebuild:** `signature-landmarks.bundle.js`,
`player-vehicles.bundle.js`, `pyramidal-roofs.bundle.js`
(`node scripts/build-3d-bundles.mjs --only=signature-landmarks,player-vehicles,pyramidal-roofs`)
and `three-buildings.bundle.js` (`npm run build:canal-three-buildings`).

## Next, measured but not fixed

- **MapLibre's per-frame overhead** (~1.5-2 ms of its 2-3 ms, outside the
  style layers): `hasTransitions` 0.3-0.4 ms a frame (an `Object.keys` walk of
  every layer's paint values), tile culling and clipping masks ~0.6, custom
  layer projection data ~0.16 (15 legacy custom layers; the shared frame
  needs 2). Candidates: an upstream patch or a cached `hasTransitions`, and
  the shared frame by default.
- **The highlight casing while a destination is lit** still draws every
  building outline on every tile (opacity 0 but the accent): a filter on the
  accent ids would cut it to one tile, but `setFilter` on the 10k-building
  GeoJSON source re-tiles it on every card change.
- **Signature landmarks CPU** (`landmarks` 0.3-0.4 ms): `_requestModels` runs
  on every `moveend` (each frame of a ride) and filters every model spec with
  `_nearby` even when nothing can load; `getBounds` with it.
- **Legacy layer draw calls**: the landmarks layer still costs 0.2-0.4 ms
  chase and 0.7-1.1 aerial after batching, mostly three's per-draw work for
  ~130 models' meshes; merging per-material across models would be the next
  step, or the shared frame by default.
- iPhone 13 (4x throttle) profile: pending.
